# RT-AURIX-Lite — Consolidated E-Trike Controller

> **Status: Architecture + host-validated firmware + board target scaffold.**
> The portable firmware core is **implemented and host-tested** (37/37 native
> tests pass). The AURIX board target is **importable into AURIX Studio** and
> **compiles headlessly** with the HighTec toolchain. On-hardware bring-up
> (Phase D0–D5) is the remaining step (requires DAS install + board).

A single **AURIX TC375** (AURIX™ Lite Kit V2) controller that combines RT
(realtime physics, steering, CAN gateway) and the former SYS (safety, brake,
body control, mode authority) into one microcontroller — **RT only, no SYS
node, no RT↔SYS intercommunication.** It keeps the same two-CAN-bus topology
as the distributed architecture and bridges between high and low buses.

## What this is

A consolidated variant of the [distributed E-Trike architecture](../architecture.md)
that runs all realtime + safety + body control on **one AURIX TC375**
(3×300 MHz TriCore: CPU0/CPU1 lockstep, CPU2 non-lockstep) instead of two
ESP32-S3s. The MTR STM32 (EGAS Level 1 motor controller) and Jetson Orin
(ROS 2 perception) remain separate.

## Key Differences from Distributed

| | Distributed | RT-AURIX-Lite |
|---|---|---|
| MCUs | 2× ESP32-S3 (RT + SYS) | 1× AURIX TC375 (RT) + MTR |
| SYS node | separate | removed (folded into RT) |
| CAN buses | 2 (high + low) | 2 (high + low) |
| CAN gateway | Yes (RT bridges) | Yes (RT bridges) |
| RT↔SYS traffic | `0x7FE`, `0x205`, `0x110`, fwd `0x011`/`0x600` | **none** |
| Cores | 2× single-core | 3× TriCore (CPU0 data plane / CPU1 ASIL lockstep / CPU2 body) |
| Runtime | 8 (RT) + 15 (SYS) = 23 FreeRTOS tasks | 15 functional units; runtime mechanism **target-gated** |

## CAN Protocol

The RT-only subset lives in [`protocol/`](protocol/) (contracts, generated
codecs/DBC/CSV/docs, vectors). It is generated by the dedicated parallel tool
[`rt-aurix-lite/protocol/tools/generate.py`](protocol/tools/generate.py)
without modifying the canonical [`protocol/`](../protocol/) tooling. Wire
layouts of retained messages are byte-identical to the canonical contracts;
only network/sender metadata changed. See [`protocol/README.md`](protocol/README.md).

## Hardware

Target: **Infineon KIT_A2G_TC375_LITE, SAK-TC375TP-96F300W AA**
(3×300 MHz TriCore; CPU0/CPU1 lockstep; 2×MCMCAN×4 nodes) — see
[`aurix.md`](aurix.md) for the board manual and [`wiring.md`](wiring.md).

- **CAN_LOW:** CAN0 Node 0 — on-board TLE9251VSJ (P20.8 TX, P20.7 RX, P20.6 STB, 120 Ω).
- **CAN_HIGH:** CAN0 Node 2 — external transceiver (TBD) on mikroBUS 13/14 (P15.0 TX, P15.1 RX).
- Rider inputs / light relays on free expansion-header pins (architecture §9).
- Added externals: 2nd CAN transceiver, TPS3850-Q1 watchdog, relay driver board.
