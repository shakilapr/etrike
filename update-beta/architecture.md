# E-Trike Rust Rewrite — Workspace Architecture

**Status:** Phase −1 (scaffolding and design). No firmware code yet.
**Scope:** A clean-room Rust reimplementation of the `rt-esp32` and `sys-esp32`
ESP32-S3 firmwares, living under `update-beta/`. The existing C++ projects are
**not modified**; this tree is a parallel implementation.

---

## 1. Goals and constraints

The rewrite exists because the C++ firmwares accumulated internal conflicts that
are hard to reason about and hard to fix in place. The Rust rewrite must:

- **Eliminate internal conflicts by construction** — one writer per piece of
  state, no ad-hoc globals, no dual synchronisation paths.
- **Keep the logic clean, simple, and single-owner** — a pure, deterministic
  core with a thin hardware shell.
- **Validate every data pipeline** — no unverified frame or input can influence
  an output.
- **Make illegal situations unrepresentable** — an ESTOP latch that cannot be
  reset while blocked; a host mode request that cannot override physical or SYS
  authority.
- **Remain wire-compatible** with the existing fleet via the authoritative
  contracts in `protocol/contracts/*.yaml`.

Non-goals for the rewrite:

- Changing the C++ projects or their PlatformIO/CMake builds.
- Changing the CAN wire contract. `protocol/contracts/*.yaml` remains the
  single source of truth; the Rust codec is generated from it.
- Adding new vehicle features. This is a correctness and clarity rewrite.

## 2. Locked decisions

| Area | Decision |
|------|----------|
| HAL / runtime | `esp-hal` 1.2.x + `embassy` (`esp-hal-embassy`, `embassy-sync`, `embassy-time`) |
| Language subset | `#![no_std]` for libraries; firmware binaries use the embassy executor |
| Workspace | Cargo workspace rooted at `update-beta/` |
| Crate names | firmware: `sys-esp32-rs`, `rt-esp32-rs`; libraries: `etrike-protocol`, `etrike-core` |
| Wire codec | Generated by extending `protocol/tools/protocol.py` with a Rust emitter |
| Implementation order | SYS first, then RT |
| First deliverable | P0 + P1 + P2 (toolchain, protocol crate, fully-tested pure core) before any HAL shell |
| `0x7B9` (brake actuator) | Single-producer: **SYS only**. RT's dead emergency-takeover fallback is dropped |
| ESTOP contract | Asymmetric clear: enter on one `0x001`/fault; clear only on validated reset evidence |

## 3. Why the rewrite: defects being resolved

**RT** (`rt-esp32/src/main.cpp`, ~1640 lines, 3 tasks)

- Safety events use a queue **and** fallback atomics, drained twice — redundant
  and racy.
- `g_estop_reason` is written from four contexts; `g_host_cmd_mailbox` is zeroed
  by three or more writers (last-writer-wins clobber).
- Dead but documented code: `brake_fallback.h` (0x7B9 takeover) never
  instantiated, `can_rx_router.h` unused, `MtrHealthSupervisor` a no-op,
  several write-never globals.
- Both CAN tasks pinned to core 0 at the same priority — time-sliced, not
  isolated.

**SYS** (`sys-esp32/src/main.cpp`, ~1671 lines, 12 unpinned tasks)

- CAN RX priority inversion, worked around with a 5 ms `xQueueSend` hack
  (SYS-BUG-02).
- `MtrEstopAckWatchdog::check_tick()` is never called, so the
  exhaustion/latch path is unreachable on-device (SYS-BUG-01).
- Documented inhibits (`kInhibitMtrFbkLoss`, `kInhibitBrakeFollowing`) are
  never set; several globals are write-never or read-never.
- Non-atomic cross-task statics; 11 copy-pasted ESTOP trigger sites; NVS
  committed on every boot.

**Shared**

- `0x7B9` has two contradictory documented models (single-producer vs Option-D
  handoff); docs claim 8/15 tasks versus 3/12 in code; `shared/can/` is
  vestigial.

This rewrite encodes the *intended* semantics once, in types, and tests them.

## 4. Architecture layers

```
┌──────────────────────────────────────────────────────────────┐
│ Shell  (sys-esp32-rs / rt-esp32-rs)                          │
│  esp-hal drivers, embassy tasks, GPIO/ADC, TWAI, SPI         │
│  Owns hardware. Converts IO <-> typed Inputs/Outputs.        │
├──────────────────────────────────────────────────────────────┤
│ Domain core  (etrike-core)                                   │
│  Pure, deterministic state machines. No HAL, no IO.          │
│  step(&mut self, Inputs, now) -> Outputs                     │
├──────────────────────────────────────────────────────────────┤
│ Wire  (etrike-protocol)                                      │
│  Generated codecs, E2E CRC, routing, typed frames,           │
│  StreamValidity, TX ownership.                               │
└──────────────────────────────────────────────────────────────┘
```

- **Wire** knows the bytes, nothing about policy.
- **Core** knows the policy, nothing about hardware or bytes.
- **Shell** knows the hardware, nothing about policy.

The dependency arrows point downward only: shell → core → wire.

## 5. Concurrency model

The system is an **event-driven control loop**, not a pool of unsynchronised
tasks.

```
                core 0                                  core 1
 ┌───────────────────────────────┐      ┌───────────────────────────────┐
 │ twai_rx ──RawFrame──► ch(RAW) ─┼─────►│                               │
 │ io/btn  ──InputEvent─► ch(EVT) ┼─────►│   ControlCore::step()         │
 │ watchdog─TaskMissed──► ch(EVT) ┼─────►│   (fixed tick + event wake)   │
 │                                │◄─────┼── Outputs                     │
 │ twai_tx ◄─TypedFrame─ ch(TX)  ─┼──────┤                               │
 │ relay/led ◄─GpioOut────────────┼──────┤                               │
 └───────────────────────────────┘      └───────────────────────────────┘
```

Rules:

1. `ControlCore` is **moved into exactly one task**. It is the sole owner of all
   decision state.
2. No logic state lives in globals, `static mut`, or atomics. Cross-task
   communication is through `embassy_sync::channel` with explicit direction.
3. Hardware tasks are thin: receive, verify, forward; or drain, serialise, send.
4. Fault detection is an *input* to the core. Task liveness is observed by the
   shell; a missed deadline becomes `InputEvent::TaskDeadlineMissed`, and the
   **core** decides whether that means ESTOP.

This removes the multi-writer races, the dual sync path, and the priority
inversion structurally rather than by convention.

## 6. Validated pipeline model

Every path through the system uses the same three-stage validation:

```
RawFrame ──verify──► Verified<TypedMsg> ──counter/freshness──► Valid<TypedMsg> ──► Inputs
   (DLC, CRC-8,             (StreamValidity)                     (the only type
    route/sender)                                                 the core accepts)
```

- `RawFrame` is inert. It cannot influence an output.
- `verify()` checks DLC, the E2E CRC (`e2e_crc`), the route table, and the
  declared sender for the `(bus, id)`.
- `StreamValidity` enforces the rolling-counter rule (delta 0 rejected,
  1 accepted, 2 accepted with one miss, >2 sequence fault; reacquisition needs a
  baseline then an advancing frame).
- Only `Valid<TypedMsg>` is accepted into `SysInputs` / `RtInputs`.
- TX ownership is generated from `network.yaml`: exactly one sender per
  `(bus, id)`, enforced at startup.

Physical inputs follow the same idea: debounced in the shell, then range- and
consistency-checked in the core into a `PhysicalInput` newtype.

## 7. Type-enforced safety invariants

These are the properties the rewrite is built around. Each is enforced by types
and covered by property tests.

### 7.1 ESTOP cannot be reset while blocked

```rust
pub struct EstopLatch { active: bool, reason: Option<EstopReason>, epoch: u32 }
pub struct ResetEvidence { source: ResetSource, blockers: ResetBlockers, now: Instant }

impl EstopLatch {
    pub fn enter(&mut self, r: EstopReason) { self.active = true; self.reason = Some(r); self.epoch += 1; }
    pub fn is_active(&self) -> bool { self.active }

    pub fn try_reset(&mut self, ev: ResetEvidence) -> ResetOutcome {
        if let Some(b) = ev.blockers.first() { return ResetOutcome::Rejected(b); }
        if !ev.source.is_valid() { return ResetOutcome::Rejected(ResetBlocker::InvalidToken); }
        self.active = false; self.reason = None;
        ResetOutcome::Cleared { epoch: self.epoch }
    }
}
```

There is no API to clear the latch without `ResetEvidence`. `ResetBlockers`
includes: physical button still pressed, latched fault active, vehicle moving,
heartbeat loss, MTR ESTOP acknowledgement pending, transient inhibit active,
invalid reset token.

### 7.2 Host mode request cannot override physical / SYS authority

SYS resolves mode in exactly one function; host `0x111` is a subordinate,
validated *request*:

```rust
pub fn resolve_authority(i: &AuthorityInputs) -> Authority {
    if i.estop.is_active() || i.latched.any() {
        return Authority { mode: Mode::Manual, power: Power::off(), clamp: Clamp::Estop };
    }
    let host_auto_ok = i.host_req.verified && i.host_req.fresh && i.host_req.wants == Mode::Auto;
    if i.physical_run && host_auto_ok && i.policy.allows_auto() {
        Authority { mode: Mode::Auto, power: Power::on(), clamp: Clamp::None }
    } else {
        Authority { mode: Mode::Manual, power: Power::from_physical(i), clamp: Clamp::None }
    }
}
```

RT never mutates mode. It mirrors SYS's `0x110` output. There is no second
writer.

### 7.3 Other invariants

- Exactly one sender per `(bus, id)` — generated `TxOwnership`, checked at
  startup.
- Same inputs ⇒ same output, regardless of event arrival order
  (`mode_is_deterministic`).
- The MTR ESTOP acknowledgement watchdog exhausts and latches — the path that
  was unreachable on-device is now exercised by test.

## 8. Repository layout

```
update-beta/
  Cargo.toml                  # [workspace] members
  rust-toolchain.toml         # xtensa-esp32s3 (via espup)
  architecture.md             # this document
  crates/
    etrike-protocol/          # wire codec wrapper + validation
    etrike-core/              # pure domain logic
  sys-esp32-rs/               # SYS firmware binary
    .cargo/config.toml        # default target xtensa-esp32s3-none-elf
  rt-esp32-rs/                # RT firmware binary
    .cargo/config.toml
```

Generated Rust lives with the other generated outputs, under
`protocol/generated/rust/etrike_protocol.rs`, so the wire contract keeps a single
home.

Per-firmware `.cargo/config.toml` files (not the workspace root) set the default
target, so `cargo test` for the two library crates still runs on the host
toolchain.

## 11. Risks and watch-items

- **esp-hal peripheral stability.** `twai`, `spi`, `rmt`, `pcnt`, and `analog`
  are behind the `unstable` feature. Pin the exact esp-hal version and keep all
  hardware specifics in the shell so API churn cannot reach the core.
- **No esp-hal driver for MCP2515 or WS2812.** Write a MCP2515 driver over
  `embedded-hal-async` SPI; drive WS2812 via RMT (or a `smart-leds` adapter).
- **Async versus hard real time.** The FTTI budget (RT↔SYS comm loss < 200 ms)
  must be re-validated. Timing lives in the shell; the core stays tick-driven
  and deterministic.
- **Scope.** P0–P2 gate all HAL work; each phase has explicit acceptance
  criteria.
- **Folder lifecycle.** `update-beta/` is a versioned-style name. The workspace
  document must state whether it eventually replaces the C++ firmwares or
  remains a permanent parallel implementation, so it does not become cruft.
